# 项目架构指南

## 项目概述

这是一个基于LangGraph和LangChain的数据集管理系统，支持智能数据分析、元数据提取和MCP服务器集成。项目采用模块化设计，支持多种执行模式。

## 目录结构

### 根目录结构
```
dataset-manager/
├── src/                    # 源代码目录
├── config/                 # 项目级配置文件
├── docs/                   # 项目文档
├── examples/               # 示例代码
├── logs/                   # 日志文件
├── metadata/               # 元数据存储
├── tests/                  # 测试文件
├── uploads/                # 文件上传目录
├── web/                    # Web前端资源
├── main.py                 # 主入口文件
├── start_dev.py           # 开发环境启动脚本
├── pyproject.toml         # 项目配置和依赖管理
└── ARCHITECTURE.md        # 详细架构文档
```

### 源代码结构 (src/)

所有源代码位于 `src/` 目录下，按功能模块组织：

#### 核心业务模块

- **core/**: 核心业务逻辑层（分层架构设计）
  - `dataset_service.py`: 数据集应用服务层，协调各个业务流程，处理复杂的业务逻辑
  - `dataset_repository.py`: 数据仓储层，负责数据持久化、缓存管理和数据访问抽象
  - `file_service.py`: 文件管理服务，处理文件上传、验证、存储和元数据提取
  - `metadata_service.py`: 元数据处理服务，负责数据集元数据的提取、分析和更新
  - `__init__.py`: 模块初始化，导出核心服务类

- **agents/**: 智能代理实现（基于LangChain的代理模式）
  - `factory.py`: 代理工厂类，负责创建和配置不同类型的智能代理
  - `__init__.py`: 模块初始化，导出代理工厂和基础代理类

- **graph/**: LangGraph工作流定义（状态机模式的分析流水线）
  - `state.py`: 工作流状态定义，包含数据分析过程中的状态结构和状态转换
  - `nodes.py`: 工作流节点实现，定义各个分析步骤的具体逻辑
  - `workflow.py`: 主工作流实现，协调整个数据分析流程
  - `builder.py`: 工作流构建器，用于动态构建和配置分析工作流
  - `__init__.py`: 模块初始化，导出工作流类和状态定义

#### 基础设施模块

- **config/**: 配置管理（统一的配置中心）
  - `settings.py`: 应用配置类，使用Pydantic管理环境变量、模型配置和系统设置
  - `agents.py`: 代理相关配置，定义不同代理的配置参数
  - `__init__.py`: 模块初始化，导出配置类和配置加载函数

- **llms/**: 语言模型接口（统一的LLM抽象层）
  - `llms.py`: 基础LLM抽象类，定义统一的语言模型接口
  - `factory.py`: LLM工厂类，根据配置创建不同的语言模型实例（DeepSeek、OpenAI等）
  - `__init__.py`: 模块初始化，导出LLM工厂和基础类

- **server/**: 服务器层（FastAPI应用层）
  - `app.py`: FastAPI应用核心配置，包含应用初始化、生命周期管理和全局配置
  - `routes.py`: 主要API路由定义，处理数据集管理、分析等核心业务接口
  - `mcp_routes.py`: MCP服务器相关的API路由，处理MCP服务器的管理和调用
  - `middleware.py`: 中间件定义，包含请求日志、CORS、安全等中间件
  - `dependencies.py`: 依赖注入管理，定义可重用的依赖项和服务注入
  - `__init__.py`: 模块初始化，导出应用实例和路由配置

#### 数据和工具模块

- **schemas/**: 数据结构定义（Pydantic模型）
  - `dataset.py`: 数据集相关的数据结构，包含数据集元数据、文件信息等模型
  - `analysis.py`: 分析结果相关的数据结构，包含分析报告、统计信息等模型
  - `mcp.py`: MCP服务器相关的数据结构，包含服务器配置、工具定义等模型
  - `__init__.py`: 模块初始化，导出所有数据模型类

- **tools/**: 工具函数和类（可重用的数据处理工具）
  - `data_analyzer.py`: 数据分析核心工具类，提供统计分析、数据质量检查等功能
  - `file_processor.py`: 文件处理工具，支持多种格式文件的读取、验证和转换
  - `visualization_tools.py`: 数据可视化工具，生成图表、报告和可视化分析
  - `__init__.py`: 模块初始化，导出所有工具类

- **utils/**: 实用工具函数（通用辅助功能）
  - `helpers.py`: 通用辅助函数，包含文件大小格式化、路径处理等工具函数
  - `json_utils.py`: JSON处理工具，提供JSON序列化、反序列化和格式化功能
  - `__init__.py`: 模块初始化，导出所有工具函数

#### 扩展模块

- **mcp/**: MCP (Model Context Protocol) 服务器（外部系统集成）
  - `servers.py`: MCP服务器管理器，管理多个MCP服务器实例的生命周期
  - `connectors.py`: 数据源连接器，支持数据库、API等外部数据源的连接和操作
  - `tools.py`: 外部工具注册表，管理可调用的外部工具和服务
  - `__init__.py`: 模块初始化，导出MCP服务器管理器和连接器

- **prompts/**: 提示模板管理（模板化的提示词系统）
  - `analysis_prompts.py`: templates文件夹下的md文件的应用
  - `loader.py`: 提示词加载器，从模板文件加载和管理提示词
  - `utils.py`: 提示词工具函数，提供模板渲染、变量替换等功能
  - `templates/`: 提示词模板文件目录
  - `__init__.py`: 模块初始化，导出提示词加载器和工具函数

## 架构设计原则

### 1. 分层架构
- **表现层**: FastAPI服务器层，处理HTTP请求
- **应用层**: 应用服务层，协调业务流程
- **领域层**: 核心业务逻辑和规则
- **基础设施层**: 数据访问、外部服务集成

### 2. 模块化设计
- 每个模块职责单一，便于测试和维护
- 清晰的依赖关系，避免循环依赖
- 支持插件化扩展

### 3. 配置驱动
- 统一的配置管理，支持环境变量
- 类型安全的配置验证
- 支持多环境配置

### 4. 异步优先
- 全面支持异步操作
- 提高并发性能
- 非阻塞的I/O处理

## 执行模式

项目支持多种执行模式：

1. **直接执行模式**: 直接调用agents中的函数
2. **工作流模式**: 使用LangGraph定义的工作流
3. **服务器模式**: 通过FastAPI提供HTTP接口
4. **MCP模式**: 作为MCP服务器提供外部工具集成

## 开发规范

### 文件命名规范
- Python文件使用snake_case
- 类名使用PascalCase
- 函数名使用snake_case
- 常量使用UPPER_CASE

### 导入规范
- 使用相对导入在同一包内
- 使用绝对导入跨包引用
- 按标准库、第三方库、本地模块的顺序组织导入

### 错误处理
- 统一的错误处理机制
- 详细的日志记录
- 优雅的错误降级

### 测试规范
- 单元测试覆盖核心业务逻辑
- 集成测试验证模块间协作
- 使用pytest框架

## 包管理规范

### 必须使用uv
- 使用 `uv` 管理所有依赖
- 不使用 `requirements.txt`
- 所有依赖在 `pyproject.toml` 中定义
- 使用 `uv add` 添加新依赖
- 使用 `uv sync` 同步依赖

### 依赖管理
```bash
# 添加新依赖
uv add package_name

# 添加开发依赖
uv add --dev package_name

# 同步依赖
uv sync

# 运行项目
uv run python main.py
```

## 扩展指南

### 添加新的LLM支持
1. 在 `src/llms/` 下创建新的实现文件
2. 继承基础LLM抽象类
3. 在配置中添加相应的配置项

### 添加新的分析工具
1. 在 `src/tools/` 下创建工具类
2. 定义清晰的接口和数据结构
3. 添加相应的测试用例

### 添加新的工作流节点
1. 在 `src/graph/` 下定义新的节点
2. 更新状态结构定义
3. 集成到主工作流中

### 添加新的MCP连接器
1. 在 `src/mcp/connectors.py` 中添加新的连接器类
2. 实现标准的连接器接口
3. 在工具注册表中注册新的工具
